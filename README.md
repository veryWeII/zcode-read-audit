# zcode-read-audit

ZCode 桌面端的**文件读取审计工具**:每轮回复末尾自动追加一个可折叠的审计区域(文件读取 + 输出速度),模型正文原文保持不变;另有 `/audit` 按需速览、实时仪表盘与按需深查。

## 功能一览

| 能力 | 形态 | 说明 |
|---|---|---|
| 每轮审计区域 | Stop hook 自动追加,默认**开** | 回复原文逐字保留、格式不动,末尾仅追加可折叠 `<details>` 区域:本轮文件读取(Read 工具与 shell 推定,行级范围、🤖 子代理标记、类型图标)+ 会话累计明细 + 输出速度(持续速率、TTFT 中位/p75,本轮/累计 × 主循环/子代理分组);0 读取的回合也展示(确认审计在工作) |
| 按需速览 | 聊天输入框 `/audit` | 默认**紧凑速览**(几行):上一轮读取数+文件名、累计次数、上一轮/累计速度与 TTFT;`/audit --full` 出完整表格;`/audit <会话ID>` 复盘指定会话 |
| 实时仪表盘 | `npm start` → http://127.0.0.1:7431 | 分会话 + 总计,每 3 秒刷新,含 shell 读取推定(紫色)、敏感文件高亮 |
| 按需深查 | 聊天输入框 `/reads` | 文件关键词 → 读没读过;会话 ID → 完整复盘(含 diff) |
| 全局审计库 | gryph SQLite | 所有工具调用落库,含敏感文件检测(.env/*.pem/.ssh 等) |

## 安装

### 方式一:ZCode 插件(推荐,零配置)

1. ZCode → 设置 → 插件管理 → 发现(Discover)→ `+` 添加市场:本仓库的 **GitHub 地址**或**本地目录**;
2. 安装 `zcode-read-audit`,完成。禁用/卸载同样在插件管理里一键操作。

插件模式零依赖即可用(每轮审计区域、行级范围、会话累计、`/audit`、`/reads`),hook 由插件自动启用,**新开的对话**立即生效。需要全局审计库(gryph)与仪表盘时,克隆本仓库走方式二。

> ⚠ 两种方式**二选一**:同时启用会双份记账、双份清单。从方式二切到方式一,先 `node setup.js --revert` 摘除旧 hooks。

### 方式二:setup.js(增强模式,含 gryph 转发与仪表盘)

```bash
# 1. 依赖:gryph(可选,没有则仅少全局审计/仪表盘)
npm i -g @safedep/gryph

# 2. 克隆本仓库后执行安装器
node setup.js

# 3. (可选)启动仪表盘
npm start
```

安装器会:探测 node/gryph 绝对路径 → 生成 `paths.json` → 备份并幂等合并 `~/.zcode/cli/config.json` 的 hooks → 安装 `/audit` 与 `/reads` 命令 → 生成 `~/.zcode/read-audit/report.js` 启动器(`/audit` 用)→ 创建数据目录 `~/.zcode/read-audit/`。

**生效时机**:hook 配置按「内部会话创建」加载——安装后**新开的对话**立即生效;已开的旧对话要等重启/上下文压缩/fork 后切换。但 Stop 静默化是个例外:hook 指向的脚本是每次调用现读的,升级本工具后旧对话的下一次 Stop 就不再强制续写。

### 设置

- `~/.zcode/read-audit/settings.json` → `{"auto": false}`:关闭每轮自动追加(Stop 仅静默转发审计事件,零打扰),报告改走 `/audit`;缺省(或删除该文件)= 开启。插件模式下也可经插件设置界面(userConfig `auto`)切换,hook 参数优先于 settings.json。
- `paths.json`(仅方式二)记录 gryph 路径/数据目录/仪表盘端口,换机器重跑 `setup.js` 再生成。

## 卸载

- 插件模式:插件管理里卸载/禁用即可,hook 随插件停止贡献;
- setup.js 模式:`node setup.js --revert`,只摘除本工具注册的 hooks 与 `/audit`、`/reads` 命令及 report 启动器,不动其他配置。

两种模式的数据目录(`~/.zcode/read-audit/`)均保留,可手动删除。

## 工作原理

```
┌─ PostToolUse ──┬─ gryph _hook claude-code PostToolUse   → 全局审计库(SQLite)
│                └─ tool-ledger.js                        → 本地账本 ledger.jsonl(回退数据源)
│
├─ Stop ────────── stop-hook.js(默认开启;auto=false 时仅静默转发)
│                    ├─ 转发负载给 gryph
│                    ├─ 取「本轮」窗口内该会话的读取记录(窗口起点=上次 Stop 的水位)
│                    │    数据源三级:① 直查 ZCode 原生库 db.sqlite(db-lookup.js,含子代理 parent_id 精确归属)
│                    │              ② 原生库不可用 → 本地账本    ③ 账本无该会话 → gryph 时间窗
│                    │    Read 工具直取路径+行范围;shell 命令(cat/head/grep/rg/sed…)推定路径
│                    ├─ ⚡ 输出速度块(speed-lookup.js):直查 model_usage,可信行口径的持续速率+TTFT,
│                    │    本轮/累计 × 主循环/子代理分组,独立 <details> 追加在读取清单之后
│                    └─ 以 {"decision":"block","reason":清单} 请求续写,续写 = **原回复逐字复读 + 末尾审计块**:
│                         正文内容/格式/顺序完全不变(不摘要、不分区、不折叠正文),只多出末尾的折叠审计区域;
│                         模型手写抢跑的清单按条款删除,脚本清单是唯一版本
│
└─ /audit ──────── report.js(按需速览,聊天命令触发)
                     ├─ 定位会话:--sid 指定,或「最近活跃根会话」自动识别(触发消息会把
                     │    当前会话顶到 session.time_updated 之首)
                     ├─ 「上一轮」窗口 = 最近两条真实用户消息之间(role=user 且
                     │    metadata.source 为空,排除 todo_reminder 等合成消息;最后一条
                     │    即 /audit 触发本身,为生成报告做的探测读取天然落在窗口外)
                     ├─ 默认紧凑速览几行,--full 出完整表格;数据源三级同上
                     └─ ⚡ 速度一行/全表:speed-lookup.js,上一轮/累计 × 主循环/子代理
```

关键设计:

- **正文不动,只追加**:续写指令要求原回复逐字复读 + 末尾追加折叠审计块——不摘要、不重新分区、不折叠正文;原始回复折进工作记录作备份,最终消息 = 原文 + 审计区域
- **不依赖模型自觉**:审计内容由脚本从审计数据计算,模型无法"忘了报"或"少报"——它只是复读
- **数据源三级**:① ZCode 原生库 `db.sqlite` 直查(主源,热库只读实测 4~25ms;子代理经 `session.parent_id` 精确归属,无留存上限,失败的工具调用尝试也计入);② 本地账本 ledger.jsonl(回退,按 payload 原始 session_id 精确匹配);③ gryph 时间窗(兜底,记账 hook 装好前的旧会话)。`part.data` 是内部格式,解析失败自动降级,不影响报告
- **会话累计**:同一遍扫描顺出该会话历史读取总数(去重文件数),以二级 `<details>` 展开按文件聚合的明细表(次数/来源构成/最近读取,按次数排序);原生库源无留存限制,回退账本时受 48h 留存限制
- **水位防抖 + 续写收尾识别**(自动模式):每会话记录上次 Stop 水位且先推水位再干活;`stop_hook_active` 为真、或「0 新读取 + 刚发过清单」的 Stop 视为续写收尾直接放行——每回合固定一次续写,不会连环触发
- **shell 读取推定**:Bash 命令按 `&&`/`;`/`|`/`(` 分段,识别读取类命令后提取路径参数(绝对路径、`./`、`../`、`~/`);`sed -i` 排除。启发式,变量拼接/命令替换的路径识别不了,展示时标注"shell 推定"
- **行级范围**:Read 工具取原生库的 offset/limit(缺省=全文),shell 识别 `head/tail -n`、`sed -n a,bp`;gryph 无行级数据,gryph 回退模式与仪表盘不显示范围
- **类型图标**:清单按扩展名标注文件图标(📜 脚本 · 🧾 json · 📝 md · 🖼️ 图片 · ⚙️ 配置 · 📦 压缩/二进制 · 📋 日志等),纯映射由脚本计算,未识别类型 📄
- **输出速度**:与文件读取同源的独立折叠块。可信行 = 完成请求且输出 ≥300 tok 且生成窗口 ≥1s;持续速率 = 可信行 Σtokens ÷ Σ生成窗口——服务端攒批下发时小输出/毫秒级窗口的单行 TPS 会假高,加权口径规避;TTFT 取全部完成请求的中位数与 p75。全程 SQL 聚合零行传输,任何异常静默降级为不展示,不影响读取清单

## 排障

- **`/audit` 报错或定位错会话**:直接跑 `node --no-warnings ~/.zcode/read-audit/report.js --sid <会话ID>` 看原始输出;默认紧凑速览,加 `--full` 出完整表格;「无已完成回合」= 该会话只有一条真实用户消息(比如就是触发命令本身),累计部分仍有效
- **每轮清单没出现**:确认 settings.json/插件设置里 `auto` 未关,再看 `~/.zcode/read-audit/.stop-debug.log` 最后几行——`auto off → silent pass` / `no sid` / `block emitted` 分别对应不同环节;`block emitted` 有了但界面没显示,则是该会话加载的还是旧 hook 配置(见"生效时机")
- **仪表盘打不开**:检查端口占用(`netstat -ano | findstr 7431`);系统代理可能拦 localhost,curl 加 `--noproxy "*"`
- **gryph 事件缺失**:长会话 transcript 大,gryph hook 可能慢——安装器已把超时设为 25s,仍丢事件时报告不受影响(走本地账本)
- **手动测试**:向脚本灌模拟负载即可,例:`echo '{"session_id":"sess_X","hook_event_name":"Stop"}' | node lib/stop-hook.js true`(末参 `true` = 强制 auto 模式;不带参数则按默认静默处理)

## 已知边界

- 报告/清单渲染最后一步仍由模型执行(指令要求逐字复读,乱改概率极低;账本/仪表盘始终是权威数据源)
- 「上一轮」按真实用户消息切窗:用户连发多条消息时,窗口取最近两条之间(即最后一个完整回合);`/audit` 自己的探测读取不计入
- 原生库 `part.data` 是 ZCode 内部格式,客户端升级可能变动——已做失败自动回退,最坏情况退回账本通道(子代理覆盖随之暂失,主会话清单不受影响)
- 自动模式:续写 = 原回复复读一遍 + 审计块,token 开销与回复长度成正比,且每回合固定一次续写(0 读取也展示,确认审计在工作);嫌吵可 `{"auto": false}` 关掉改走 `/audit`
- 单轮清单上限 20 条、累计明细上限 30 个文件(超出提示用 `/reads` 查全量);账本回退时受 48h 留存限制
- ZCode 插件体系无自定义 UI 面板扩展点,折叠表格(`<details>`)是聊天 Markdown 体系内的最优形态
